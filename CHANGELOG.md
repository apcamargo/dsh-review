# Changelog

## Unreleased

- Added `--timeout <seconds>` to `/review`: a per-run fleet timeout parameter. The flag (integer seconds, 1–2147483 — a missing value, a non-integer, or an out-of-bounds value answers the flag's error; duplicates: last wins; requires `--deep`) sets BOTH worker limits — reviewers and verifier lanes — for that review only, and raises the call-budget headroom to at least (1 + retries) × each limit so a timed-out worker's in-call retry actually fits. The merge happens at the fleet's begin (where the settings resolve once per run), not the command handler; a live review's settings are deep-frozen, so the flag never changes a run that already began, and `deep_review_scan` re-calls finish pending reviewers under the settings the review began with. The start message names the effective worker limit and budget; `/review status` shows the hint. `--extra "--timeout 900"` still stores the literal (both flag forms are guard values now). Default `deep.reviewerTimeoutMs` rises from 900 s to 1200 s.
- Config: `deep.callBudgetMs` now scales when unset — at least (1 + retries) × the worker timeouts, max over both kinds, derived after the timer clamps and clamped to MAX_TIMER_MS. With the 1200 s default timeout equal to the old 1200 s default budget, a full-timeout worker's in-call retry was dead by construction and wave-2+ workers were budget-cut before their own timeout fired; the unset-budget floor fixes the default pair and the config-timeout-only hole (`deep.reviewerTimeoutMs: 1800000` alone now yields a 3600 s budget). An explicitly-configured budget stays a cap — silently raising a user's explicit cost cap would violate it, and the four budget-pinning runtime tests keep their small explicit budgets.

- Config: the reviewer and static-verifier pool defaults drop from 4 to 3 (`deep.concurrency` / `deep.verifierConcurrency`) — three concurrent LLM streams per pool instead of four lowers the concurrent-connection pressure on the provider path (the last observed `--deep` usage lost two of six reviewers to one simultaneous connection-reset event while three workers streamed). The executing (reproducer) pool is unchanged at 2: reproducers run tests in the shared working tree. The total-run caps (`deep.maxReviewers` 12, `maxVerifierRuns` 40) are unchanged — a pool slot frees and starts the next pending item, so total runs still reach the caps; the verify-budget test's scripted pool arithmetic is updated to the new default.

- Config: the reviewer per-worker timeout default rises from 10 to 15 minutes (`deep.reviewerTimeoutMs` 600000 → 900000). In the last observed `--deep` usage the consistency lens was killed by the fleet at exactly 600,003 ms while still mid-analysis (57 steps, 73 tool calls, zero failed requests — 88s of that in whole-home `find` sweeps and 16 upstream `curl` calls cross-checking pyodide-build), so the cap, not a failure, decided what the review saw. The verifier limit is unchanged (600000), and a reviewer that burns its full limit stays bounded by `deep.callBudgetMs` and the retry loop's aborted check.

- Fixes (fleet reliability): each reviewer now gets one in-call retry — the same attempt loop the verifier units keep (`deep.verifierRetries`) — before its roster entry is declared failed, behind the new `deep.reviewerRetries` (default 1). In the last observed `--deep` usage two of six reviewers (correctness, propagation) died from one mid-stream provider failure each (`litellm.APIConnectionError` — the chunked response was severed, `Connection reset by peer`; both within 2.4s of each other while three workers streamed), and nothing re-spawned them: a worker whose single LLM attempt ends `finish: error` fails its entry, its lens stays uncovered for the whole review, and recovery needed a manual `deep_review_scan` re-call the orchestrator never made. The aborted check re-runs before each attempt, so a spent budget, a cancelled turn or an unloaded fleet breaks instead of re-spawning into an abort (a budget-killed worker is still not retried; the spent-call contract returns what is pending). A persistently-failing worker still ends failed after exactly one retry per call (regression-tested: a first-attempt failure is recovered by the in-call retry with no re-call, and a doomed worker runs exactly twice per scan call and still fails).

- Fixes (web deployment): the deep fleet's reviewer-tool visibility check now resolves `deep.reviewerTools` against the calling session's tool view — `ctx.tools.get(name, parent)`, the scoped lookup the tools service itself uses for a call (`this.get(name, agent)` in createExecution) — instead of a no-scope `ctx.tools.get(name)`, which reads the host composition's GLOBAL layer only. The web-app bundle moves every model-facing tool behind per-session presets on the agent plane (its patch disables the base's host `tool-bash`/`tool-fs`/`tool-fs-search` rows and lets each session mount a preset instead), so the global view reads "bash" as absent in a web deployment and every reviewer of a passing session failed with `the configured reviewer tool "bash" is not visible to this session` — a deterministic failure the scan's "Call deep_review_scan again to retry them" steer could never recover. A genuinely missing tool still fails loud with its name (regression-tested over a preset-scoped web-profile-shaped tool view).

- Fixes (evaluation round 2): -z path parsing no longer trims — filenames with leading/trailing whitespace are legal and tracked verbatim, so the working-tree snapshot now stats the exact path (both snapshots recording "deleted" under the trimmed key silently disabled the "files changed during review" guard for such a file) and the untracked roster entry resolves the exact filename, matching the verbatim numstat parse. `resolveDeepConfig` now re-checks the lane entry shapes — a non-object lane value (`reproducer: "off"`) and a non-boolean `enabled` would pass validation and be silently ENABLED at runtime, so a user disabling the mandatory lane got it run; both throw with the field path. `/review --extra "--deep"` — an explicitly-quoted literal — is no longer answered with "Missing value for --extra": control-vs-value is decided on the raw remainder after `--extra` (the instructions path's own convention; `--extra=--deep` already stored the literal, and the bare `--extra --deep` is still the control word the guard rejects).

- Deep review fixes (evaluation round): a scan above `deep.minReviewerSuccess` with failed reviewers now counts for verification — `deep_review_verify` and the stop gate share one quorum notion (`scanCounted`), so one persistently-failing reviewer above quorum (whose doomed worker each scan re-call re-runs) can no longer leave verification permanently unreachable and the review ends with zero verification; failed reviewers' scopes are uncovered, the coverage line reports the success count, and the verify gate names the fraction and the pending or failed reviewers. The folder walk now names every non-regular entry — a symlinked directory inside a reviewed folder, a FIFO — in the coverage note with per-path reasons instead of a silently complete walk. Dead stores on the run record (`run.scan.result`, `run.scan.rendered`, `run.verify.rendered`, `run.verify.tree`) are dropped; only `run.verify.classified` is consumed beyond the stored results.

- Review-finding fixes (independently adversarially re-verified): the citation gate now confines every cited path to the reviewed worktree before it stats or reads — evidence paths are LLM-authored (the verifier lanes' normalized results) and reach `node:fs` directly, so an absolute or `../`-escaping path, and a worktree-internal symlink whose realpath escapes, is refused without reading (≤10 MB host reads and an existence oracle over files outside the worktree; the contract is containment, not spelling: an absolute path that resolves inside the worktree is allowed). The working-tree snapshot now rides `git status --porcelain -z` beside `git ls-files -m -d -o` — the latter lists the worktree against the index only, so a mid-review `git add`/`git mv`/`git rm` was invisible and the before/after snapshots matched, silently off for the "files changed during review" guard (status also answers 0 on a repository with no commits, where `git diff HEAD` would fail; the parse skips the rename-source NUL record a staged rename emits, so the source is not hashed as a phantom "deleted"). `/review status` and `/end-review status` now render `Pipeline: gone` for a deep record whose in-memory fleet cleared on restart, instead of an active review with no pipeline line (the README says the status says so). A failed review-turn send after `begin` + durable write now rolls the deep run back (the converse of the durable-write rollback; the durable record still says active, so `/end-review done` recovers). `--extra` answers "Missing value" for every form the partition accepts directly after it (`--deep=true`, `--aggressive=false`, `--extra=...` were silently consumed as the value); `--aggressive=false` and any other `--aggressive=<value>` but the tolerated `=true` now answer the flag's error instead of silently enabling the mode (symmetric with `--deep`). A fleet worker whose provider ignores the composed signal and resolves `completed` across an abort now answers not-ok with the cancel or per-run timeout diagnostic (the configured limit stays hard; the worker re-runs). A `bash` command with more substitution spans than the worker guard inspects (the 8/12 caps) now denies the command outright instead of passing because its first spans were clean. A duplicated `deep.lenses` name throws instead of running the lens's reviewers twice; the returned deep settings are deep-frozen over a clone (freezing never side-effects the caller's config object); a drifted rubric split marker fails loud at load instead of silently truncating the rubric; and the folder walk's dot-dir convention (skip all but `.agents`) is documented in the walk and the README.

- Review-finding fixes (independently adversarially re-verified): the read-only worker guard now denies the ref/file write options of the whitelisted read `git` subcommands — `git branch -d/-D/-m/-M/-c/-C/-f/-t/-u/--delete/--move/--copy/--force/--track/--set-upstream-to/--unset-upstream/--edit-description` and `git show/log/diff/blame --output=<file>` (real-git verified writes; the same ref-write class the subcommand deny list covers for checkout/reset/stash/rebase) — and the no-space redirect to an absolute path (`git show HEAD >/abs/f`), closing the `>/` slip the space form never had. A scan with nothing to verify — zero findings, or every finding dropped — now completes with an explicit empty consolidation: the previously-advertised "skip deep_review_verify" escape was impossible and dead-ended the stop gate into a false incomplete marker. The verify input hash hashes dropped ids only (drop reasons never reach the lanes; a reworded reason no longer rejects a re-call whose purpose is finishing pending workers); a real git failure inside a repository propagates at the working-tree snapshot instead of silently turning the "files changed during review" guard off (only outside-a-repo answers null, settled by an explicit `isRepo` guard); the guard-absence warn names the remote-provider cause it can verify; and the folder walk names dangling symlinks and unreadable files in the coverage note instead of a silently complete walk.
- Added `/review --deep`: fleet review mode. A scan stage runs one fresh reviewer per lens (correctness, failure paths, security, contracts, consistency, propagation; performance opt-in) in a bounded pool, sharding large diffs; the orchestrator consolidates and groups the raw findings; and a verification stage of independent adversarial lanes (reproducer, skeptic, consistency, provenance, impact, fix-auditor) judges each consolidated finding blind to the orchestrator's reasoning and to every other lane. A deterministic moderator combines the lane stances (refutation via the gating lanes needs two independent dimensions to agree; the provenance filter dismisses a citation-verified pre-existing or intentional finding regardless of gate status), a citation gate checks cited evidence against the real files, and only verified findings reach the report. `--aggressive` reports unproven findings as low-confidence suspicions; the final filter is unchanged without the flag.
- Deep reviews compose with every mode and with `--extra`, stored instructions and `--aggressive`. User-typed messages during a deep review are handed to every worker started after them (the first pinned, caps noticed); the stop gate steers an orchestrator that stops before the verifiers ran (at most twice, per-turn pause where the user spoke), and a deep-aware `/end-review` summary reads the verified report only.
- Deep config under `deep`: provider, per-role agent options, lenses, reviewer tools, reviewer/verifier concurrency and timeouts, per-call budget, cost caps, per-lane settings and steering caps. The two deep tools are registered through a per-agent scope while a deep review is active, so sessions without a deep review never see them.
- Regular reviews are unchanged: prompts are snapshot-tested, no tools are registered, and the `tools`/`subagents` services are optional (the fleet is mounted by a `ctx.inject` child fiber).

- Deep review fixes (adversarial-verified): a spent call budget now returns what is pending instead of rejecting the scan or verify call with a misleading "cancelled" (bookkeeping I/O around the pools is not budget-bounded); the regular review path commits the durable write before queueing the review turn (a failed write no longer leaves an untracked review the model performs); the executing guard allows the bare test runners the reproducer lane documents (`npm test`, `pnpm test`, `yarn test`) while keeping install subcommands denied; the static guard denies find's `-delete/-exec/-ok`/write options, `sort -o`, piped shells, quoted denied words, and inspects `$(…)`/backtick content; the citation gate checks line-specific evidence against the actual span of the nearest occurrence of the quoted text, so a right-quote-wrong-place citation no longer verifies (a correct citation whose quote repeats through the file still verifies against the occurrence it cites); failure diagnostics from a pool-callback error always reach the orchestrator; a concurrent `/review --deep` for a session with a live deep review errors instead of orphaning the live run; and an outside-git `folder` review walks only the requested paths.
- Deep review config is now schema-enforced: the entry exports `Config` (validated by cordis at start with field paths, the dsh-storage-domain convention), the three timer fields carry upper bounds, and `resolveDeepConfig` re-checks the cost-cap floors at `/review --deep` time — previously-silent invalid values (`maxReviewers: 0` yielded a silent empty scan; `maxSteeringEntries: 0` popped the pinned first steering entry) now throw with a user-facing message.
- Deep review hardening (adversarially verified): the reproducer's best-effort guard now also denies find's write/execute options and `sort -o` (the static profile's own check — previously an executing-only gap that allowed `find . -delete` in the shared working tree); a completed, faithful review is never released with the incomplete marker (the steer-budget release guards on the pipeline state) and a mid-pipeline marker clears when verification completes; a verifier unit that omits an assigned ref fails instead of falsely succeeding, so the finding is retried instead of permanently withheld; the verify input hash is normalized — identical consolidation reordered proceeds, and different args after completion throw instead of silently returning the stale stored result; the user's stored instructions, `--extra` text and project REVIEW_GUIDELINES.md ride to every fleet worker (the agents doing the flagging now see what the rubric's precedence rules are written against); the three timer fields carry the same 1000 ms floor the schema declares (negative/zero/fractional values no longer reach `AbortSignal.timeout` as RangeErrors or 1 ms aborts); a spent scan budget below quorum returns what is pending instead of rejecting with the quorum error; a complete verification answers only identical re-calls idempotently; folder-snapshot coverage names unreadable directories; numstat parsing reads `-z` output (non-ASCII filenames and rename paths land in the roster correctly, exact quotes in such files pass the citation gate); the spent-call warning names failed reviewers too; and schemastery is declared a regular dependency, matching the dsh-storage-domain convention.

- Deep review fixes (adversarially re-verified): `resolveDeepConfig` now re-checks the lane sub-fields the schema cannot — a negative/zero/fractional lane `chunkSize` (which would hang the verify planning's chunk loop in a proven infinite synchronous loop, host kill required) and a non-number (which would silently collapse to one empty chunk, the lane never assessing any group) throw with a user-facing message, and lane/top-level `agentOptions` shapes are re-checked so a malformed shape cannot reach the subagent start as silent garbage. `deep.lanes.<id>.agentOptions` is now applied: per-lane options merge (undefined-filtered before the spread, config.js's own convention) over `verifierAgentOptions` inside the subagent seam, where the provider's agentOptions capability check covers the final options — previously the documented field was accepted, validated and never read. The citation gate stats the cited path and refuses content above a distinct high cap (10 MB — cited files legitimately exceed the 1 MB snapshot-hashing cap; ≥512 MB reads already failed every quote via the V8 string limit) and paths that are not regular files (directories, never-EOF devices). A completed verification persists its result before setting the completion state, so the invariant "state complete ⇒ result stored" is unconditional (the impossible "complete with no result" stuck state left the idempotent early-return answering undefined forever). The gate's release marker no longer claims "the orchestrator stopped responding" when reviewers persistently fail — it names the gate's own release semantics, a cause it can verify. In-repo folder reviews list untracked net-new files under the requested paths (agreeing with the outside-repo walk — an untracked src/new-module.js reaches the roster or the file-local lenses never review it). The steering overflow notice names the oldest dropped entry instead of the last. The teardown-ordering comments name what cordis actually guarantees (a fiber's top-level disposables run in parallel — the fleet aborts reach the deep runs immediately, the drain/scope disposal may interleave with the domain close, which is safe: the deep tools never write the storage domain); `renderFindings` drops its dead `moderated`/`hasDiff` params; the empty consistency note reaches its "matches the codebase" fallback; and the devDependencies install the full test-time closure — including dsh-tools's own `dsh-sandbox` peer, which dsh-tools statically imports — so a fresh `npm install --omit=peer` keeps `npm test` green.

- Renamed the review output section "Human Reviewer Callouts (Non-Blocking)" to "Side Effects & Breaking Changes (Non-Blocking)" and added the missing feature-flag and config-default items to the summary handoff, which now matches the review rubric's eight items.
- `/review commit`, `/review pr` and `/review folder` without an argument now answer with a usage line. They used to fail with a `TypeError`.
- Git and `gh` calls fail fast. Truncated output, signal exits and unexpected exit codes are errors, and `/review pr` no longer checks out a branch when `git status` cannot be read. A missing `git` is reported as such, not as "Not a git repository".
- `/review pr` validates the reference before running `gh` or `git`, ignores untracked files when it checks for pending changes, and reports unexpected `gh pr view` output as an error. A failed checkout shows the end of the `gh` diagnostic, where the cause is.
- Git runs with repository-local environment variables (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, …) removed and with prompts and pagers disabled.
- Unloading the plugin cancels commands that are still running and waits for them before closing the review state.
- An unreadable `REVIEW_GUIDELINES.md` now fails the review instead of being skipped silently.
- Review turns carry their own message source, `apcamargo-dsh-review`, instead of posing as user input.
- Added plugin list metadata (`locale/en.json`), completed the type declarations, and declared the `dsh-storage-domain` and `dsh-subprocess` peer dependencies.
